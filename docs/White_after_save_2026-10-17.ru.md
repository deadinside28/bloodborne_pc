# Белая сцена после смены сохранения — 2026-10-17

**Дополнение вечером 17.10:** цветные блоки без Bloom воспроизведены также
при первой загрузке. Найдена отдельная регрессия частичного live-патча SSR;
полный стартовый патч даёт нормальную сцену и с включённым Bloom. См.
`SSR_corrupt_load_2026-10-17.ru.md`. Ниже сохранены первоначальные наблюдения;
найденный дефект согласования кешей сам по себе не доказывал причину белизны.

Пользователь в одном процессе загрузил сохранение, вышел и загрузил другое.
На втором сохранении сцена почти полностью белая, HUD виден.

## Наблюдения

- Процесс 160872, лог `20261017_124103.log`. Validation не загружена.
- Первый участок работал около 96–99 FPS. После смены сейва были
  интервалы 9–12 FPS со stalls около 500–600 мс, позднее около 77 FPS.
  Это разные сцены, поэтому разницу стабильного FPS нельзя целиком приписать

  известных контекстов. Большинство старых объектов уже переиспользованы;

## Найденный дефект и изменение

`FxInitClear` отправляет приватные PM4 WRITE_DATA для трёх служебных целей
истории FX. При New путь `Rasterizer::WriteDataOnGpu` обновлял буфер памяти
игры, но не сообщал кешу текстур об изменившихся байтах. В отличие от CPU-пути
через `NoteCommandWrite`, уже существующая Vulkan-текстура могла оставаться
со старым содержимым. При первой загрузке текстура ещё может отсутствовать
в кеше; повторная загрузка и повторное использование адресов выявляют дефект.

После GPU-записи размером больше 8 байт вызывается существующий механизм
`TextureCache::InvalidateMemoryFromGPU`: изображение с тем же начальным
адресом, полностью покрытое записью, получает `GpuDirty` и обновляется из памяти
при следующем использовании. Проверка `guest_size <= max_size` предотвращает
перезаливку целого GPU-изображения из устаревшей памяти при частичной записи.
Скалярные fence/label записи сохраняют прежний быстрый путь.
Обработка произвольных частичных записей внутрь изображения этим изменением
не расширяется: существующий API рассматривает изображения с совпавшим началом.

Это исправление реального нарушения согласованности кешей, но связь именно
этого дефекта с наблюдаемым белым кадром пока не подтверждена. Большие
задержки кадров также требуют повторного измерения после исправления.

## Проверка и ограничения

Сборка bbgpu и native-тесты fx-init-clear, cp-decoder,
effect-flags прошли. Они проверяют команды очистки, декодер и предыдущее исправление
SSAO; не заменяют проверку повторного использования Vulkan-текстуры в игре.
Лог первоначальной проверки: `build-test.log`; окончательная сборка после
ограничения по размеру изображения — `build-test-final.log`.

Отдельный AppImage для проверки:
`dist/Bloodborne-bbport-x86_64-white-reload-test.AppImage`.
Основной AppImage этой проверкой не заменяется. Игра автоматически не запускалась.
Нужна ручная проверка той же последовательности двух сохранений в новом
процессе. Уже запущенный процесс продолжает использовать прежнюю библиотеку.
Дополнительные дампы можно получить при следующем запуске через
`BB_IMAGE_SYNC_LOG=1`, `BB_DUMP_TRIGGER`, `BB_DUMP_DIR`, `BB_DUMP_FRAMES=1`.
